# 땅따먹기 (방치형 영토 정복) 설계서

작성일: 2026-09-05 · 상태: 사용자 검토 대기

## 1. 한 줄 요약

아이폰 사파리에서 여는 웹페이지 방치형 게임. 육각 타일 지도에서 성(타일)을 업그레이드해
골드와 병사를 생산하고, 병사를 옆 땅에 보내 정복한다. AI 세력이 같은 규칙으로 경쟁하며,
지도를 전부 정복하면 환생해서 영구 보너스를 사고 더 큰 지도에서 다시 시작한다.
꺼둔 시간도 양쪽(나·AI) 모두 시뮬레이션되고, 전멸하면 강제 환생한다.

## 2. 확정된 결정 (사용자 답변)

| 항목 | 결정 |
|---|---|
| 장르 | 성마다 생산력·병사, 업그레이드, 옆 땅 정복 |
| 템포 | 방치형 + 환생 |
| 실행 | 아이폰 브라우저용 웹페이지, GitHub Pages 배포 |
| 상대 | AI 경쟁 세력 있음 |
| 환생 조건 | 지도 정복 시 환생, 전멸 시 강제 환생 |
| 오프라인 | 꺼둔 시간 동안 나·AI 양쪽 다 시뮬레이션 |
| 그래픽 | 무료 CC0 에셋(Kenney) 사용 |
| 구현 | 순수 HTML + Canvas, 프레임워크·빌드 없음 (사용자 "맘대로"로 위임) |

## 3. 게임 규칙

### 3.1 지도
- 육각 타일, 반지름 R의 정육각형 판. 타일 수 = 3R(R+1)+1.
- R = min(3 + floor(환생횟수/2), 6) → 37 / 61 / 91 / 127 타일.
- AI 세력 수 = min(2 + floor(환생횟수/3), 4).
- 수도: 플레이어는 판 가장자리 한 꼭짓점, AI는 나머지 꼭짓점에 최대한 멀리 배치.
- 지형 4종을 시드 난수로 배정(수도는 항상 '성채').

| 지형 | 골드 계수 | 방어 보너스 | 병사 한도 계수 |
|---|---|---|---|
| 평지 | 1.0 | 0 | 1.0 |
| 숲 | 1.5 | +20% | 1.0 |
| 언덕 | 2.0 | +50% | 1.2 |
| 산 | 3.0 | +100% | 1.5 |
| 성채(수도) | 3.0 | +100% | 2.0 |

- 중립 타일 초기 수비병 = 8 × (1 + 플레이어 수도로부터의 거리 × 0.6) × (1 + 환생횟수 × 0.15), 정수 반올림.

### 3.2 타일 상태
- 소유자(없음/플레이어/AI n), 레벨 L(1~10), 병사 수(실수, 표시는 정수), 지형.
- 골드 생산/초 = 0.5 × 지형골드계수 × L × 세력생산배율
- 병사 생산/초 = 0.15 × L × 세력병사배율, 한도 = 20 × L × 지형한도계수 까지만 찬다.
- 업그레이드 비용 = 40 × 1.7^(L−1) × (지형골드계수) 골드. 레벨 10이 최대.
- 골드는 세력 단위 공용, 병사는 타일 단위.

### 3.3 전투
- 조작: 내 타일 탭(선택) → 인접 타일 탭.
  - 인접이 적/중립: 공격. 선택 타일 병사의 파병 비율(25/50/100%, 기본 50%)만큼 보냄.
  - 인접이 내 땅: 같은 비율만큼 이동(보강). 한도 초과분은 버려지지 않고 그대로 유지(초과 상태에서는 생산만 멈춤).
- 공격력 A = 보낸 병사 × 세력공격배율. 방어력 D = 수비 병사 × (1 + 지형방어보너스).
  - A > D: 점령. 새 수비 병사 = (A − D) / 세력공격배율. 소유자 교체, 레벨 유지.
  - A ≤ D: 실패. 수비 병사 = (D − A) / (1 + 지형방어보너스). 공격병 전멸.
- 즉시 판정. 화면에는 0.4초 짧은 이동 연출만 있고 규칙엔 영향 없음.
- 수도에 특권은 없다(성채 지형 보너스뿐). 수도가 점령당해도 타일이 하나라도 남으면 그 세력은 계속 진행.

### 3.4 AI
- 세력마다 행동 주기 T초 = max(2, 6 × (1 − AI둔화보너스)). 주기마다 한 번:
  1. 업그레이드: 골드가 비용 이상이면 자기 타일 중 레벨이 가장 낮은 타일(동률이면 지형 골드계수가 높은 쪽) 하나를 업그레이드. 골드가 남으면 반복(주기당 최대 3회).
  2. 공격: 자기 타일 중 병사 ≥ 10인 타일마다, 인접한 남의 타일 중 (병사×0.8×공격배율) > (수비×(1+방어)×1.2)인 타일을 고른다. 우선순위 중립 > 플레이어 > 다른 AI, 같은 부류면 수비 약한 순. 한 주기에 최대 2회 공격, 80% 파병.
  3. 보강: 인접에 남의 땅이 없는 내부 타일이 한도 50% 이상이면 절반을 인접한 국경 타일 중 병사가 가장 적은 곳으로 이동(주기당 1회).
- AI도 골드·병사 생산 규칙은 플레이어와 동일. 환생마다 AI 생산배율 = 1 + 환생횟수 × 0.1.

### 3.5 시간 진행
- 화면이 켜져 있을 때: 250ms 틱. 생산은 dt 비례, AI는 자기 타이머로 발동.
- 꺼둔 시간(오프라인): 다음 로드 시 경과 = now − lastSave, 상한 = 8시간 + 유산 '오프라인 한도' 보너스(최대 24시간).
  - 5초 단위 굵은 틱으로 같은 시뮬레이션을 돌린다(생산·AI 모두).
  - 끝나면 정산 창: 경과 시간, 얻은 골드, 늘어난/잃은 타일 수. 도중에 전멸했으면 강제 환생 창.
  - 도중에 플레이어가 지도를 다 먹는 일은 플레이어가 행동하지 않으므로 없음.

### 3.6 환생
- 조건: 플레이어가 모든 타일 소유(정복) 또는 타일 0개(전멸, 강제).
- 유산 포인트:
  - 정복: 10 + floor(타일수 / 4) + floor(내 타일 레벨 합 / 10)
  - 전멸: floor(이번 판 최대 보유 타일 수 / 4) (최소 1)
- 환생 시 지도·타일·골드 초기화, 환생횟수 +1, 새 R·AI 수로 재생성.
- 유산 상점(영구, 비용 = 기본 × 1.5^현재레벨, 포인트로 구매):

| 항목 | 효과/레벨 | 최대 | 기본비용 |
|---|---|---|---|
| 풍요 | 골드 생산 +10% | 20 | 5 |
| 징집 | 병사 생산 +10% | 20 | 5 |
| 무기 | 공격배율 +5% | 20 | 8 |
| 초기 병력 | 시작 수도 병사 +20 | 10 | 4 |
| 오프라인 한도 | +4시간 | 4 | 10 |
| AI 둔화 | AI 주기 +8% 지연 | 5 | 12 |

### 3.7 시작 상태
- 플레이어 수도 L1, 병사 30 + 초기병력 보너스, 골드 100. AI 수도 L1, 병사 30, 골드 100.

## 4. 화면 (세로 모드 기준)

- 상단 바: 골드 · 골드/초 · 환생 n회 · 유산 포인트 · ≡ 메뉴.
- 지도(Canvas, 화면 대부분): 한 손가락 드래그 팬, 두 손가락 핀치 줌, 탭 선택. 타일에 지형 그림, 소유자 색 테두리, 병사 수, 레벨 점.
- 하단 패널(선택 타일): 지형·소유자·레벨·병사/한도·생산량, [업그레이드 (비용)], 파병 비율 25/50/100 토글, 안내 문구 "옆 땅을 탭하면 공격/이동".
- 창: 오프라인 정산, 환생(포인트 안내 → 확인), 유산 상점, 메뉴(설정: 초기화, 저장 내보내기/가져오기 텍스트).
- iOS 대응: `viewport-fit=cover`, 홈화면 추가용 manifest·apple-touch-icon, 더블탭 확대 방지, 캔버스 `touch-action:none`.

## 6. 코드 구조 (ES 모듈, 빌드 없음)

| 파일 | 역할 | 의존 |
|---|---|---|
| `index.html`, `style.css` | 뼈대·레이아웃 | – |
| `src/rng.js` | 시드 난수 | – |
| `src/hex.js` | 축좌표 육각 격자 수학(이웃, 거리, 픽셀 변환) | – |
| `src/world.js` | 지도 생성(반지름, 지형, 수도 배치, 중립 수비) | rng, hex |
| `src/sim.js` | 순수 시뮬레이션: tick, attack, move, upgrade, 승패 판정 | hex |
| `src/ai.js` | AI 결정(상태 → 행동 목록), sim으로 적용 | sim, hex |
| `src/offline.js` | 경과 시간 굵은 틱 시뮬레이션 + 정산 요약 | sim, ai |
| `src/prestige.js` | 유산 포인트 계산, 상점, 새 판 파라미터 | – |
| `src/save.js` | localStorage 저장/로드/버전 이관 | – |
| `src/render.js` | 캔버스 그리기, 카메라, 에셋 로드 | hex |
| `src/ui.js` | DOM 패널·창·입력(탭/팬/핀치) | – |
| `src/main.js` | 게임 루프 배선 | 전부 |

- sim/ai/offline/prestige/world/hex는 DOM을 전혀 모르는 순수 모듈 → Node에서 바로 테스트.
- 상태 객체 하나(`state`)를 sim 함수들이 받아 수정. 구조: `{version, legacy{points, upgrades, prestigeCount}, run{seed, radius, factions[], tiles[], aiTimers[], maxTilesOwned, sendRatio}, lastSave}`.

## 7. 저장

- localStorage 키 `landgrab.save.v1`. 5초마다, 그리고 `visibilitychange`/`pagehide` 때 저장.
- `version` 필드로 이관. 내보내기 = JSON 문자열 복사, 가져오기 = 붙여넣기.

## 8. 테스트 (`node --test tests/`)

- hex: 이웃 6개, 거리, 반지름별 타일 수.
- world: 반지름·AI 수 공식, 수도 간 최소 거리, 중립 수비 증가.
- sim: 생산·한도, 업그레이드 비용·상한, 전투 성공/실패 수식, 이동, 정복/전멸 판정.
- ai: 유리할 때만 공격, 우선순위, 업그레이드 선택.
- offline: 상한 적용, 1시간 경과 결과가 250ms 틱 결과와 ±5% 이내(생산만 있을 때는 정확히 일치).
- prestige: 포인트 공식, 상점 비용, 최대 레벨.
- 밸런스(시나리오): ① 플레이어가 아무것도 안 하고 10분 → 수도가 남아 있다(초반 즉사 방지). ② 탐욕 스크립트 플레이어가 2시간 시뮬 안에 R=3 지도를 정복한다. ③ AI끼리만 30분 → 어느 AI도 전체를 먹지 못한다.
